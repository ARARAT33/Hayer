# HAYER համայնքների և հաղորդակցության մոդել

## Որոշման առաջարկ

HAYER-ը պետք է վերցնի երեք հարթակների ուժեղ կողմերը, բայց չկրկնօրինակի դրանց սահմանափակումները.

- **Reddit-ի մոդել՝ հանրային համայնքների համար**. համայնքներ, թեմատիկ գրառումներ, մեկնաբանությունների ծառ, upvote/downvote, պահպանված գրառումներ, նոր/թրենդային դասավորում։
- **Discord-ի մոդել՝ համայնքի կառուցվածքի համար**. մեկ համայնք = առանձին տարածք (server); ներսում՝ տեքստային ալիքներ, հայտարարություններ, կանոններ, դերեր, ադմիններ և մոդերատորներ։ Փակ/մասնավոր տարածքների մուտքը հրավերով կամ հաստատմամբ։
- **Telegram-ի մոդել՝ արագ հաղորդակցության համար**. անձնական չատ, խմբային չատ, ալիքներ, թեմաներ, ֆայլերի փոխանակում, ձայնային/տեսազանգերի հետագա աջակցություն։

### HAYER-ի առաջարկվող նավիգացիա

1. **Feed** — HAYER-ի բոլոր հրապարակումները՝ բաժանված «Բաժանորդագրված», «Թրենդային», «Նոր»։
2. **Համայնքներ** — որոնում, կատեգորիաներ, հանրային/փակ համայնքներ, անդամակցություն և մոդերացիա։
3. **Համայնքի ներսում** — «Գրառումներ» և «Ալիքներ» ներդիրներ։ Գրառումները Reddit-ի նման են, ալիքները՝ Discord/Telegram-ի նման։
4. **Chat** — անձնական և խմբային հաղորդագրություններ՝ Telegram-ի նման։
5. **Calls** — ձայնային/տեսազանգեր՝ առանձին WebRTC/RTC ծառայության տեխնիկական ստուգումից հետո։
6. **Create (+)** — գրառում, համայնք, ալիք, խումբ կամ հարցում ստեղծելու մեկ միասնական կոճակ։
7. **Admin & moderation** — համայնքի սեփականատեր, ադմին, մոդերատոր, report, block, mute, spam control։

## Հարթակների համեմատություն

| Հարթակ | Ուժեղ կողմը | HAYER-ի համար կիրառումը | Սահմանափակում |
|---|---|---|---|
| Telegram | Արագ chat, խմբեր, ալիքներ, Mini Apps | Անձնական/խմբային հաղորդակցություն, Mini App մուտք | Bot API-ն չի տալիս Telegram-ի ամբողջական ներքին տվյալների բազան կամ անվճար HAYER backend |
| Discord | Server-ներ, channel-ներ, դերեր, voice | Համայնքի կառուցվածք, թեմատիկ ալիքներ, դերեր | Discord API-ն սահմանափակված է Discord-ի սեփական սերվերներով/հաշիվներով. Activity-ի կառուցման ուղեցույցը ենթադրում է ծրագրավորման գիտելիք և backend |
| Reddit | Subreddit-ներ, post/comment, vote | Հանրային քննարկումներ և համայնքային Feed | Reddit-ը HAYER-ի սեփական հաշիվների ու անկախ տվյալների պահեստի փոխարինող չէ |
| Discourse | Կարգավորված ֆորում, թեմաներ, moderation, բաց API | Լավագույն լրացուցիչ թեկնածուն՝ Reddit-անման քննարկումների համար | Պետք է ունենալ/վարձել Discourse instance. API-ն ինքնին հոստինգ չի տրամադրում |
| Zulip | Թեմաներով կազմակերպված chat, ալիքներ, real-time events և REST API | Ավելի լավ այլընտրանք է, եթե առաջնայինը կարգավորված խմբային chat-ն է | Ավելի շատ թիմային հաղորդակցություն է, քան հանրային սոցիալական feed. պետք է Zulip server |


## Ինչն է տեխնիկապես կարևոր

- Telegram Mini Apps-ը կարող է ապահովել Telegram-ի ներսում բացվող HAYER UI և փոխանցել Telegram-ի հաստատված օգտատիրոջ տվյալները։ Բայց դա ինքնին HAYER-ի տվյալների բազա կամ անվճար մշտական backend չէ։
- Discord Activities-ը ներկառուցված վեբ հավելվածներ են Discord-ում։ Պաշտոնական ուղեցույցի օրինակն ունի frontend և backend մասեր, հետևաբար «առանց կոդի և առանց backend-ի» լուծում չէ։
- Reddit-ի և Discord-ի API-ները նախատեսված են համապատասխան հարթակների հետ աշխատելու համար։ Դրանք չպետք է դիտարկել որպես HAYER-ի սեփական, անսահմանափակ, անվճար ենթակառուցվածք։
- HAYER-ի Feed-ում պետք է ցուցադրվեն միայն HAYER-ում ստեղծված գրառումները։ Արտաքին ցանցերի ընդհանուր feed-ը չպետք է խառնվի դրան։

## Ինչու են Discourse-ը և Zulip-ը ավելի լավ լրացուցիչ թեկնածուներ

- **Discourse**-ը բաց API-ով ֆորումային շարժիչ է. ունի categories, topics, posts և private messages։ Այն Reddit-ի նման համայնքային քննարկումների համար ավելի հարմար է, քան Telegram/Discord API-ները, բայց պետք է հյուրընկալվող Discourse instance. API-ն ինքնուրույն անվճար սերվեր չի տրամադրում։
- **Zulip**-ի REST API-ն ընդգրկում է channels, topics, messages, users, subscriptions և real-time events։ Այն հատկապես լավ է կառուցվածքային խմբային հաղորդակցության համար, բայց չի փոխարինում Reddit-ի նման հրապարակային feed-ին։
- **Reddit Data API**-ն ունի rate limit-եր և բովանդակության ջնջման/պահպանման կանոններ։ Այն HAYER-ի սեփական տվյալների հիմնական պահեստ դարձնելը լավ ընտրություն չէ։
- **Telegram Mini Apps**-ը լավագույնն է որպես Telegram-ի ներսում բացվող հավելվածի shell, ոչ թե որպես ամբողջ HAYER-ի backend։

## Ընտրության առաջարկ

**Արտադրանքի UX-ի համար ընտրել Hybrid HAYER՝ Reddit + Discord + Telegram։** Սա երեք ծառայությունների տեխնիկական միացում չէ. սա HAYER-ի սեփական փորձառությունն է՝ վերցնելով դրանց լավագույն գաղափարները։

**Տվյալների/հոստինգի որոշումը առանձին է։** Ներկայիս main branch-ը Matrix-ի վրա հիմնված հաճախորդ է։ Այն չի կարելի լուռ փոխարինել նոր backend-ով կամ Base44-ով՝ առանց հաշիվների, հաղորդագրությունների, համայնքների և տվյալների միգրացիայի պլանի։

## Առանց կոդի կառուցման հարթակների մասին

Base44-ը կարող է AI-ով ստեղծել հավելված, ունի ներկառուցված auth և database, բայց անվճար պլանն ունի ամսական AI և integration credit սահմանափակումներ։ Այն հարմար է փորձնական տարբերակ կառուցելու համար, ոչ թե անվճար և անսահմանափակ HAYER-ի երկարաժամկետ երաշխիք։

FlutterFlow-ի Free պլանը թույլ է տալիս կառուցել և փորձարկել, բայց APK ներբեռնումը և source-code արտահանումը վճարովի պլաններում են։ Bubble-ի անվճար պլանը development/testing-ի համար է, իսկ live production հրապարակումը վճարովի է։

## Հաջորդ իրականացման փուլը

1. Համաձայնեցնել Hybrid UX-ը՝ Feed, Communities, Channels, Chat, Calls։
2. Նկարագրել տվյալների մոդելը և դերերի/մուտքի կանոնները։
3. Համեմատել հարթակների իրական անվճար quotas-ը և արտահանման հնարավորությունները։
4. Ընտրել այնպիսի հիմք, որտեղ HAYER-ի տվյալներն ու կոդը հնարավորինս տեղափոխելի են։
5. Միայն դրանից հետո փոխել ներկայիս Matrix ինտեգրումը։
