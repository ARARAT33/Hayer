# ՀԱՅԵՐ — միասնական հայկական համայնք

ՀԱՅԵՐ-ը բաց, բազմահարթակ համայնքային էկոհամակարգ է, որը միավորում է անկախ սոցիալական, հաղորդակցական, ֆորումային և մեդիա ծառայությունները։ **Օգտատերը սեփական սերվեր, VPS, դոմեն, տվյալների բազա կամ API բանալի չի տրամադրում։** Կայքը կարող է աշխատել որպես ստատիկ GitHub Pages հավելված, իսկ հանրային կատալոգը թարմացվում է GitHub-hosted Actions-ով։

## Սկզբունքային պահանջ

**Ոչ մի արտաքին սերվեր կամ կատալոգ չպետք է լինի միակ խափանման կետը։** Եթե 10 հանգույցից 5-ը անհասանելի են, մյուս 5-ը պետք է շարունակեն աշխատել՝ պայմանով, որ տվյալ ծառայության ֆեդերացիան/հաճախորդը և տվյալները հասանելի են։

Սա չի նշանակում, որ ցանկացած ծառայություն ավտոմատ կշարունակի աշխատել ցանկացած 50% խափանման դեպքում։ Յուրաքանչյուր պրոտոկոլ ունի իր սահմանափակումները. օրինակ՝ Matrix-ի տվյալները պահվում են homeserver-ներում, իսկ Mastodon-ի հաշիվը կապված է կոնկրետ instance-ի հետ։ Մի սերվերի տվյալները մյուս սերվերներում ինքնաբերաբար չեն կրկնօրինակվում։

## Միասնական հաշիվ և բաշխված տվյալներ

HAYER-ի պահանջվող օգտատիրոջ փորձը՝ մեկ գրանցում, մեկ HAYER ID, և ոչ մի ձեռքով սերվեր/JSON/API կարգավորում։ Սակայն միայն ստատիկ GitHub Pages-ը չի կարող անվտանգ պահել հաշիվների տվյալներ կամ տրամադրել համընդհանուր OIDC մուտք։ Դրա համար անհրաժեշտ է արտաքին կառավարվող նույնականացման ծառայություն (օրինակ՝ OIDC մատակարար) և դրա թույլատրելի կոնֆիգուրացիա։ Սա դեռ չի միացված, ուստի այս տարբերակը դեռ չի տրամադրում իրական HAYER գրանցում։ Արտաքին Matrix/Mastodon/Lemmy/PeerTube հաշիվների SSO-ն հնարավոր է միայն այն instance-ներում, որոնց օպերատորները թույլատրում են այն։

HAYER ID-ը HAYER-ի ներսում օգտատիրոջ միասնական անունն ու պրոֆիլի նույնացուցիչն է։ Այն ինքնաբերաբար չի դառնում Matrix, Mastodon, Lemmy կամ PeerTube հաշիվ։ Մեկ մուտք (SSO) հնարավոր է միայն այն հանրային instance-ներում, որոնց օպերատորները բացահայտորեն վստահում են համապատասխան արտաքին նույնականացման մատակարարին։ Մանրամասն՝ [հանրային ֆեդերացիայի ճարտարապետություն](./docs/PUBLIC-FEDERATION-ARCHITECTURE.md), [միասնական հաշվի սահմանափակումներ](./docs/SINGLE-ACCOUNT-ARCHITECTURE.md) և [անվտանգության մոդել](./docs/SECURITY-MODEL.md)։

Նախագծում պահպանված `backend/` պանակը նախկին սերվերային նախատիպ է և չի գործարկվում HAYER-ի հանրային, առանց սեփական սերվերի տարբերակում։ Այն չի պահանջվում կայքը բացելու կամ հանրային կատալոգը թարմացնելու համար։

## Տեխնոլոգիական սահմանափակումներ

HAYER-ի հիմնական հավելվածը ստատիկ կայք է՝ GitHub Pages-ի համար։ VPS չի պահանջվում։ GitHub Actions-ը պարբերաբար հավաքում և հրապարակում է հանրային կատալոգը։ Բրաուզերը չի կարող վստահելիորեն ստուգել ցանկացած արտաքին սերվերի առողջությունը. CORS-ը, rate limits-ը և status endpoint-ների բացակայությունը կարող են վիճակը դարձնել անհայտ։ «Անհայտ»-ը երբեք չպետք է հավասարեցվի «խափանված»-ին։

## Ռեեստրի ձևաչափ

Տե՛ս [registry.schema.json](./registry.schema.json) և [հանրային ֆեդերացիայի ճարտարապետությունը](./docs/PUBLIC-FEDERATION-ARCHITECTURE.md)։

## Տեղային գործարկում

Բացիր `index.html` ֆայլը բրաուզերում կամ օգտագործիր ցանկացած ստատիկ հոսթինգ։ GitHub Pages-ը կարող է հրապարակել `main` ճյուղի արմատային թղթապանակը։

## Անվտանգություն

- Մի ներմուծիր կամ մի պահիր արտաքին հաշիվների գաղտնաբառերը։
- Արտաքին instance-ները համարիր չվստահված։
- Մի ցուցադրիր չստուգված instance-ները որպես «աշխատող»։
- Մինչև անչափահասների գրանցումը ստուգիր յուրաքանչյուր ծառայության տարիքային պայմանները, մոդերացիան և տվյալների քաղաքականությունը։
- Սերվերների ռեեստրի աղբյուրները պետք է լինեն հրապարակային, թույլատրելի և պարբերաբար ստուգվող։
