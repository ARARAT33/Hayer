# ՀԱՅԵՐ — միասնական հայկական համայնք

ՀԱՅԵՐ-ը բաց, բազմահարթակ համայնքային էկոհամակարգի նախագիծ է։ Նպատակն է մեկ գլխավոր կայքի միջոցով միավորել անկախ սոցիալական, հաղորդակցական, ֆորումային և մեդիա ծառայությունները։

## Սկզբունքային պահանջ

**Ոչ մի արտաքին սերվեր կամ կատալոգ չպետք է լինի միակ խափանման կետը։** Եթե 10 հանգույցից 5-ը անհասանելի են, մյուս 5-ը պետք է շարունակեն աշխատել՝ պայմանով, որ տվյալ ծառայության ֆեդերացիան/հաճախորդը և տվյալները հասանելի են։

Սա չի նշանակում, որ ցանկացած ծառայություն ավտոմատ կշարունակի աշխատել ցանկացած 50% խափանման դեպքում։ Յուրաքանչյուր պրոտոկոլ ունի իր սահմանափակումները. օրինակ՝ Matrix-ի տվյալները պահվում են homeserver-ներում, իսկ Mastodon-ի հաշիվը կապված է կոնկրետ instance-ի հետ։ Մի սերվերի տվյալները մյուս սերվերներում ինքնաբերաբար չեն կրկնօրինակվում։

## Միասնական հաշիվ և բաշխված տվյալներ

HAYER-ի նպատակը մեկ գրանցումն է՝ մեկ HAYER ID-ով։ Արտաքին հարթակների հետ ինտեգրումը կատարվում է միայն տվյալ ծառայության թույլատրած SSO/OIDC, OAuth համաձայնության կամ օպերատորի կողմից հաստատված provisioning API-ի միջոցով։ Կամայական հանրային սերվերում աննկատ հաշիվ ստեղծել կամ դրա տվյալների բազան օգտագործել հնարավոր և թույլատրելի չէ։ Մեծածավալ ֆայլերի համար նախատեսվում է առանձին HAYER Storage Agent՝ client-side encryption-ով և տարբեր օպերատորների միջև կրկնօրինակմամբ։ Մանրամասն՝ [միասնական հաշվի և տվյալների ճարտարապետություն](./docs/SINGLE-ACCOUNT-ARCHITECTURE.md) և [անվտանգության մոդել](./docs/SECURITY-MODEL.md)։

## Տեխնոլոգիական սահմանափակումներ

Առաջին փուլը ստատիկ կայք է՝ GitHub Pages-ի համար։ VPS չի պահանջվում։ Բրաուզերը չի կարող վստահելիորեն ստուգել ցանկացած արտաքին սերվերի առողջությունը. CORS-ը, rate limits-ը և status endpoint-ների բացակայությունը կարող են վիճակը դարձնել անհայտ։ «Անհայտ»-ը երբեք չպետք է հավասարեցվի «խափանված»-ին։

## Ռեեստրի ձևաչափ

Տե՛ս [registry.schema.json](./registry.schema.json)։

## Տեղային գործարկում

Բացիր `index.html` ֆայլը բրաուզերում կամ օգտագործիր ցանկացած ստատիկ հոսթինգ։ GitHub Pages-ը կարող է հրապարակել `main` ճյուղի արմատային թղթապանակը։

## Անվտանգություն

- Մի ներմուծիր կամ մի պահիր արտաքին հաշիվների գաղտնաբառերը։
- Արտաքին instance-ները համարիր չվստահված։
- Մի ցուցադրիր չստուգված instance-ները որպես «աշխատող»։
- Մինչև անչափահասների գրանցումը ստուգիր յուրաքանչյուր ծառայության տարիքային պայմանները, մոդերացիան և տվյալների քաղաքականությունը։
- Սերվերների ռեեստրի աղբյուրները պետք է լինեն հրապարակային, թույլատրելի և պարբերաբար ստուգվող։
